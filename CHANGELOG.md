## Unreleased — XENO ECOSYSTEM, sixth stage (endogenous repair, world-state intervention, reachable recovery; engine unchanged, meos-0.4)

* No engine change: the baseline result digest `b4cf1e52…` and trace digest `bd3e5886…` are unchanged, the 264 stored runs replay 264/264, Stage 5 results reproduce identically. World-state actions are built only from existing operations (`RECONFIGURE` of coupling / renewal / reserve parameters, `ALTER_RESOURCE` pulse, `RECONNECT`, `ADDRESS` restore / reassign, `ROUTE`); observation repair is applied to the analysis of recorded runs, never to a run.
* Internal reconfiguration (class A), world-state repair (class B) and observation repair (class C) are kept apart; cost is reported raw and normalised, never as a weighted total. Protocol: exploration seeds 1-5, validation 6-10, evaluation 11-30; near misses are kept and make a stress INCONCLUSIVE.
* Recovery criterion corrected during finalisation: a horizon counts only if at least 2W = 60 ticks follow the action (the first criterion, all three horizons at every tick, hid repairs after tick 120; its results are kept as `*_all_horizons_criterion.json`).
* Experiments M-Q (`xzr/meos/repair6.py`, `stage6_experiments.py`, `stage6_refine.py`, `stage6_controllers.py`, `stage6_cross.py`, `stage6_final.py`): repairability is conditional on stress, action, magnitude, tick and horizon; restoring the original parameter alone does not recover; the repair site differs from the damage site; the pulse effect is non-monotone (insufficient, effective, overshoot with secondary collapse); some repairs recover only in combination. Three windows (coupling pulse, Address restore + pulse, renewal restart + pulse) are `OPEN_THROUGH_TESTED_LIMIT` at tick 330: `irreversible_tick` is null, no closure is claimed.
* Controllers (none / fixed / rule-based / cost-aware / delayed / noisy), unknown-stress and false-positive tests, MFS / SSS / observation x repairability, failure taxonomy.
* Service: `/api/meos/repair-library`, `/repair-run`. Interface: repair panel, recovery map, three-horizon view, Address three-way table, MFS repairability table, replay markers, research-map repair layers, technical repair figure, deep links `stress` / `repair` / `ract`.
* Performance: interleaved paired Stage 5 / Stage 6 measurement with a fixed 5 % rule; overall verdict INCONCLUSIVE (no regression confirmed; one planned-series flag, habitat static p99, did not replicate and is reported).
* `docs/ECOSYSTEM_MEOS_STAGE6.md` (generated by `backend/scripts/make_stage6_doc.py`), results `docs/ecosystem/experiments_stage6*.json` and CSVs.
* Follow-up, engine `meos-0.5` (opt-in; baseline digests and every earlier result unchanged, re-run and identical): the three windows still effective at tick 330 were measured on to tick 1140 with the longest horizon the engine accepts (1200) and closed for the settings measured (closure ticks 389 coupling, 384 renewal stopped, 384 Address; in every case the repair works exactly when A1's energy at the start of the intervention tick reaches its firing cost, and the 5-tick difference is A1's energy at tick 300; with a common history and the upkeep set to 0 after tick 300 the window stays open; no action restoring A1's energy exists, so this is not a universal irreversibility); the three actions the main experiments could not build (`coupling.bypass`, `resource.rerouting`, `address.temporary_local`) were built as minimal mechanisms and run with the same protocol (alone only the coupling stress is repaired; on the renewal-efficiency, renewal-stopped and Address stresses they repair in combination with a restoration). Performance: a 12-pair final series and an A/A control (identical builds): no regression meeting the pre-set criterion was detected in 48 measures (10 shown not to be a 5 % regression, 38 inconclusive); verdict INCONCLUSIVE; the A/A shows the same uncertainty on the tails, which limits what the method can decide. Reproducibility: the validation and evaluation runs were regenerated at run level (265 settings, 6475 runs, all equal to the saved summaries); backend suite 807 tests, 805 passed, 2 known failures.

## Unreleased — browser edition

* The interactive simulator runs in a browser tab at `/app/` of the public site: the engine on Pyodide (CPython on
  WebAssembly, numpy + pydantic) in a Web Worker, same in-process interface as the iOS app, no simulation server
  (`docs/WEB_RUNTIME.md`; `backend/scripts/export_web_runtime.py`, `npm run build:web`).
* Cooperative sessions for hosts without threads: `Session.pump`, `run_deferred`, `bridge.tick`; branch comparisons are
  generators (`compare_steps`) advanced in time slices, so the live simulation keeps running during a comparison. The
  threaded path (desktop, iOS) is unchanged; `compare()` drives the same generator straight through.
* `_compat` index arrays use `np.intp` (32-bit on WebAssembly); `resource` is optional; reference hierarchies for the two
  10,000-node benchmarks; `XZR_MAX_NODES_COMPUTED_HIERARCHY` refuses graphs whose hierarchy would need the cubic dense
  eigensolver (browser: 1,500).
* Measured and documented: the browser engine is structurally identical to the desktop and numerically equal to ~1e-13 over
  1,000 steps, not bit-identical (WebAssembly math library, summation order); a browser-specific golden guards replay.

## 0.2.0 — research toolkit release

* `xzr` command (`run`, `validate`, `presets`, `compare`, `export`, `study`, `--version`), installed as a console
  script; `python -m xzr` works from a source checkout.
* Five experiment presets with documented question, manipulated / fixed variables, measured outputs and what they
  do not show: `resolution-escalation`, `history-reentry`, `boundary-scale-window`, `ablation`, `smoke`.
* Result schema `xzr.result/1`: effective configuration, seeds, provenance (version, code hash, git commit and
  dirty flag in a source checkout, Python / numpy), per-condition statuses, warnings, failures; runs never
  overwrite and write only their own directory (the published calibration cache is read, not written).
* History operations on retained memory (`xzr/experiments/history.py`): fork, removal, additive reactivation,
  migration; paired sign-flip statistics against a noise branch; an HRGI-style verdict only when retained prior
  difference, re-addressability, actual re-entry and downstream difference are all measured.
* Comparison of runs labels status cells as same / changed / newly detectable / extinguished / missing, and
  configuration sensitivity across conditions; no "novelty" label.
* Configuration validation refuses unknown or misspelt settings; the expanded configuration printed by
  `xzr validate` can be edited and run.
* `run_conditions` takes the first engine seed; `provenance()` records version and does not attribute an
  enclosing repository's commit to an installed copy.
* Post-Active-Inference benchmark (`research/post_active_inference/`, isolated; nothing in `backend/` changed for it):
  a discrete Active Inference comparator (math vendored from `ziran-xeno-simulator`), a model-light controller, an
  operational-shape tracker, 47 perturbation subtypes in 8 families, an empirical regime classifier, ablation-based
  non-redundancy tests, smoke / development / pre-registered confirmatory stages. Confirmatory result (30 seeds,
  55,680 runs): primitive instability replicates for sensor and action-interface disruptions only; where the
  primitives fail, control fails with them — see `REPORT_RESEARCH.md`. Raw per-cell jobs are excluded from version
  control and re-creatable.
* Repository: LICENSE (MIT), CITATION.cff, CI workflow (lint, types, tests, CLI smoke, two-run reproducibility
  check), docs THEORY / EXPERIMENTS / REPRODUCIBILITY, README rewritten for researchers; per-seed raw jobs of the
  long studies (~1.8 GB), run logs and a machine-specific orchestration script are excluded from version control.
